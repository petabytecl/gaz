# Phase 53.1 Plan 01: Cobra Startup + EventBus Lock Fix Summary

Shared startServices() consolidates Cobra/Run startup paths; EventBus uses snapshot-under-lock with tombstone channels for deadlock-free Publish/Close

## What Was Done

### Task 1: Cobra Single Startup Path (Rule 2)

Extracted `collectNonWorkerServices()` and `startServices(ctx)` from the inline code in `Run()`. Both `Run()` and Cobra's `Start()` now delegate to `startServices()` which provides:
- Worker filtering (workers managed by workerMgr, not DI layer)
- Parallel layer startup (goroutine per service in each layer)
- Panic recovery (via error channel pattern)
- Rollback on failure (Stop previously started services)
- Worker manager start

Also refactored `doStop()` in `app_shutdown.go` to use the shared `collectNonWorkerServices()` helper, eliminating the duplicated worker filter.

### Task 2: EventBus Lock-During-Blocking-IO (Rule 1)

Replaced the RLock-held-during-channel-sends pattern with snapshot-under-lock:

1. **Publish**: Snapshots handler slice under RLock, releases lock, delivers outside lock. Select includes `<-h.tombstone` to short-circuit cancelled subscriptions.

2. **Close**: Sets `b.closed=true`, closes all tombstones (NOT ch), releases lock, waits for handler goroutines. No ch close avoids send-on-closed-channel panic from snapshot holders.

3. **unsubscribe**: Removes subscription from map and closes tombstone under lock, releases lock, then waits for handler goroutine outside lock.

4. **Handler run()**: Watches both ch and tombstone. On tombstone, drains remaining buffered events and exits cleanly.

- **Found during:** Task 1

**2. [Rule 1 - Bug] TestCobraStartServicesMatchesRun timing race**
- **Found during:** Task 2
- **Issue:** Worker OnStart was not called before test assertion because the supervisor goroutine hadn't been scheduled yet (RunE returned immediately, triggering PostRunE Stop)
- **Fix:** Made RunE wait on a channel that closes when workerMgr calls OnStart
- **Files modified:** cobra_test.go
- **Commit:** 1b077e7

**3. [Rule 1 - Bug] EventBus ch close causes send-on-closed-channel panic**
- **Found during:** Task 2
- **Issue:** Plan prescribed closing ch after tombstone, but Go's select panics on send-to-closed-channel even with other ready cases. The existing TestEventBus_ConcurrentClosePublish caught this immediately.
- **Fix:** Close does NOT close ch at all. Handler exits via tombstone drain pattern instead of range-over-closed-ch.
- **Files modified:** eventbus/bus.go
- **Commit:** 1b077e7
