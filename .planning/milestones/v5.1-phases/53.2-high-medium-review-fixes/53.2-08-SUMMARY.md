## Changes by Requirement

### B11 -- Empty health checks -> StatusUnknown

`health/internal/checker.go`: When no checks are registered, the checker now returns `StatusUnknown` instead of `StatusUp`. This prevents false-positive readiness signals during startup before health checks have been configured. The handler already maps `StatusUnknown` to 503 (same as `StatusDown`), so the HTTP layer required no code changes -- only the handler_test was updated to expect 503 for empty checkers.

### B12 -- Logger SetDefault side-effect

`logger/provider.go`: Removed the hidden `slog.SetDefault(logger)` call from `NewLoggerWithWriter`. Added a new exported `SetGlobal(l *slog.Logger)` function. `app_build.go` now calls `logger.SetGlobal(a.Logger)` explicitly after creating the logger during `App.Build()`. This makes the global side-effect visible and controllable.

### B13 -- Logger file permissions hardened

`logger/provider.go`: Log file open now uses `0o640` (owner rw, group r, others none) instead of `0o644`. Added `syscall.O_NOFOLLOW` to prevent symlink attacks. Added `filepath.Clean` and `..` rejection to prevent path traversal.

### B15 -- gaztest TOCTOU in RequireStart/Stop

`gaztest/app.go`: Replaced the mutex lock-check-unlock-do-lock-set pattern with `sync.Once` for both `RequireStart` and `RequireStop`. The `cleanup()` method now uses the same `stopOnce`, ensuring idempotency between explicit `RequireStop()` calls and automatic cleanup via `t.Cleanup()`.

### B19 -- Cron wrapper fast-path on cancelled appCtx

`cron/wrapper.go`: Added `w.appCtx.Err()` check at the start of `Run()`. When the app context is already cancelled (shutting down), the job skips execution entirely -- no lock acquisition, no resolution, no logging overhead.

### B20 -- Worker supervisor OnStop after failed OnStart

`worker/supervisor.go`: After `OnStart` returns an error, the supervisor now calls `OnStop` with a fresh 30s timeout context. This ensures partially-initialized workers can release resources (file handles, connections, goroutines) even when startup fails.

### B21 -- Backoff ticker goroutine leak

`backoff/ticker.go`: Added `case <-t.ctx.Done(): return nil` to the `send` method's select statement. Previously, if the context was cancelled while `send` was blocked trying to write to the `t.times` channel (nobody reading), the goroutine would leak indefinitely.
