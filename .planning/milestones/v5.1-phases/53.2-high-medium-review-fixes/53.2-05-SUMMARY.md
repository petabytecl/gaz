# Phase 53.2 Plan 05: Server Layer MEDIUM Fixes Summary

Deferred gRPC server construction to OnStart, added sync.Once for health adapter idempotent close, and fixed Connect rate limit error codes to use connect.CodeResourceExhausted.

## Changes Made

### Task 1: gRPC Deferred Construction + Health Adapter sync.Once

**B7 - gRPC server constructed in OnStart not NewServer:**
- Added `serverOpts []grpc.ServerOption` field to Server struct
- Changed `NewServer` to store options instead of creating gRPC server immediately
- Added `s.server = grpc.NewServer(s.serverOpts...)` at the start of `OnStart`
- Added nil guard in `OnStop` for pre-OnStart shutdown safety
- Updated `GRPCServer()` doc to note nil return before OnStart
- Updated test to verify nil before OnStart, non-nil after

**B8 - Health adapter double-close panic prevention:**
- Added `stopOnce sync.Once` field to healthAdapter struct
- Wrapped `close(s.stopCh)` in `s.stopOnce.Do(func() { close(s.stopCh) })` for idempotent close
- Moved `s.health.Shutdown()` to `defer` to ensure it runs on both success and timeout paths
- Added `TestHealthAdapter_DoubleClose` test verifying no panic on repeated Stop calls

**Commit:** 07d9bec

### Task 2: Connect Rate Limit Error Code Fix

**B9 - Connect rate limit uses proper error code:**
- Changed unary handler from `fmt.Errorf("rate limit: %w", err)` to `connect.NewError(connect.CodeResourceExhausted, err)`
- Changed streaming handler identically
- Clients now receive proper gRPC/Connect status code (ResourceExhausted) instead of a generic error string

**Commit:** cb39e43
