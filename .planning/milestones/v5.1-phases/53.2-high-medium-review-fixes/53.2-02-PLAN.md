**A9 -- Failed Build locks container:**
In `Build()`, inside `buildOnce.Do`, move the `c.built = true` assignment to ALWAYS execute, not just on success. Place it at the end of the `buildOnce.Do` closure, after the eager resolve loop, regardless of whether `c.buildErr` was set:
```go
c.buildOnce.Do(func() {
    // ... collect and sort eager services ...
    for _, svc := range eagerServices {
        if err := c.resolveEager(svc); err != nil {
            c.buildErr = fmt.Errorf("di: building eager service %s: %w", svc.Name(), err)
            // Do NOT return here -- fall through to set built=true
            break
        }
    }
    // Always lock down registration, even on failure
    c.mu.Lock()
    c.built = true
    c.mu.Unlock()
})
```

**B3 -- Duplicate Named detection in Register:**
In `Register()`, after the built check, detect duplicate named registrations. When a name already has entries AND the registration is a Named() call (not a multi-binding group), return ErrDuplicate. The detection logic: if `len(c.services[name]) > 0`, this is a duplicate. However, multi-binding (via `For[T]()` without explicit Named) uses the type name as key and appends -- that is valid. The distinction is: `RegistrationBuilder.Replace()` sets a flag that calls `ReplaceService` instead of `Register`. So `Register` is always an append for group bindings. For Named registrations, the caller in `registration.go` should check for duplicates before calling `Register`.

In `di/registration.go`, in the `build()` method (around line 98-125), before calling `c.Register(b.name, svc)`, check if the name is explicitly set (via Named()) and if a service already exists:
```go
if b.named && b.container.HasService(b.name) && !b.replace {
    return fmt.Errorf("%w: %s", ErrDuplicate, b.name)
}
```
This requires that the `RegistrationBuilder` tracks whether `Named()` was called. Check if `b.named` or equivalent field exists. If not, add `named bool` field set to `true` in the `Named()` method.
