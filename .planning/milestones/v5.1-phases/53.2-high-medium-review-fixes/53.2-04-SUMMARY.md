## Changes Made

### B2: DI Inject Reflect Memoization
- Added `injectFieldCache` (sync.Map) to cache parsed inject field metadata per reflect.Type
- Created `getInjectFields(t reflect.Type)` that parses struct tags once and caches the result
- Refactored `injectStruct` to use `getInjectFields` instead of re-parsing on every call
- Added `TestInjectFieldMemoization_CacheHit` and `TestGetInjectFields_Idempotent` tests

### B5: Discovery Type Check Before Resolve
- `discoverWorkers` now checks `svc.ServiceType().Implements(workerType)` before calling `ResolveByName`
- `discoverCronJobs` now checks `svc.ServiceType().Implements(cronJobType)` before resolving
- Cached `workerType` and `cronJobType` as package-level vars for efficient interface checks
- Avoids unnecessary singleton instantiation during Build for non-worker/non-cron services

### B6: doStop Cached Services
- Added `cachedNonWorkerServices` field to App struct
- `startServices` caches the computed service set after `collectNonWorkerServices()`
- `doStop` uses cached set with fallback to re-walking container if Stop called without Run
- Protected access with App.mu to prevent data race between concurrent start/stop

### B16: WithConfig/MergeConfigMap Panic to Error
- `WithConfig` now appends to `buildErrors` instead of panicking when called after Build
- `MergeConfigMap` now returns error instead of panicking when called after Build
- Added `TestWithConfigAfterBuild_ReturnsError` and `TestMergeConfigMapAfterBuild_ReturnsError`

### B17: Critical-fail Handler Logging
- Critical-fail handler now logs Stop error with `log.Warn` when async shutdown completes with errors
- Previously discarded the error with `_ = a.Stop(ctx)`

### B18: ResolveGroup Type Error
- `ResolveGroup` now returns `ErrTypeMismatch` when type assertion fails instead of silently filtering
- Matches the error pattern already used by `ResolveAll`
- Added `TestResolveGroup_TypeMismatch` and `TestResolveGroup_CorrectType` tests

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Race condition on cachedNonWorkerServices**
- **Found during:** Task 2 (B6 implementation)
- **Issue:** The `cachedNonWorkerServices` field was written in `startServices` and read in `doStop` without synchronization, causing data races detected by `go test -race`
- **Fix:** Protected read/write of `cachedNonWorkerServices` with the existing `App.mu` mutex
- **Files modified:** app_run.go, app_shutdown.go
- **Commit:** 2168171

**2. [Rule 3 - Blocking] WithConfigManager does not exist**
- **Found during:** Task 2 (B16 implementation)
- **Issue:** Plan referenced `WithConfigManager` method at lines 286-289 of app.go, but this method does not exist in the codebase
- **Fix:** Applied panic-to-error conversion to `WithConfig` and `MergeConfigMap` which are the actual config methods that panic after Build
- **Files modified:** app.go
- **Commit:** 2168171

## Decisions Made

1. Used `sync.Map` for inject field cache -- provides lock-free concurrent reads which is ideal for a write-once-read-many cache keyed by reflect.Type
2. Protected `cachedNonWorkerServices` with existing `App.mu` rather than introducing a new mutex, since access patterns are simple (single write, single read)
3. `MergeConfigMap` returns error directly (not via buildErrors) since it already has an error return type -- more idiomatic Go than accumulating errors that may never surface
