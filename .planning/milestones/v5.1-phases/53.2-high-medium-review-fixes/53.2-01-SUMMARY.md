## Changes Made

### A1: Force-Exit Race Fix (app_shutdown.go)
Added a non-blocking re-check of the `done` channel after `timer.C` fires. This eliminates the TOCTOU race where shutdown could complete between the timer firing and `callExitFunc(1)` being called.

### A2: Cron Scheduler OnStop (cron/scheduler.go)
- Removed `defer s.mu.Unlock()` from OnStop
- Added `select { case <-cronCtx.Done(): case <-ctx.Done(): }` for deadline-aware shutdown
- `s.cron.Stop()` is called under lock (required because internal cron.Stop sends on a channel and cannot be called concurrently), but the blocking wait happens outside the lock (Rule 1)

### A3: EventBus OnStop (eventbus/bus.go)
- Added `CloseWithContext(ctx context.Context) error` method with per-subscription deadline via `select { case <-sub.done: case <-ctx.Done(): }`
- Changed `OnStop` from `OnStop(_ context.Context)` to `OnStop(ctx context.Context)` delegating to `CloseWithContext`
- Existing `Close()` now delegates to `CloseWithContext(context.Background())` for backward compatibility

### A4: Worker Manager Stop (worker/manager.go)
- Changed `Stop() error` to `Stop(ctx context.Context) error`
- Replaced unbounded `m.wg.Wait()` with `select { case <-m.done: case <-ctx.Done(): }`
- Updated all callers: `app_shutdown.go`, `worker/manager_test.go`, `worker/example_test.go`, `gaztest/examples_test.go`

### A5: Cron Internal Stop Documentation (cron/internal/cron.go)
- Added doc comment explaining the waiter goroutine leak limitation and the recommended `select` pattern for callers

### A6: Worker Filter Verification
- Confirmed `collectNonWorkerServices()` is defined in `app_run.go:49` and shared by both `startServices()` (line 68) and `doStop()` in `app_shutdown.go` (line 63). No code change needed.

### A13: Signal Handling Fix (app_run.go)
- Added `watcherDone` channel to synchronize watcher goroutine exit before `handleSignalShutdown` returns
- This ensures `signal.Stop(sigCh)` in `waitForShutdownSignal` does not run while the watcher is still selecting on `sigCh`

### Regression Tests
- `TestForceExitRaceSlowShutdown` (shutdown_test.go): Verifies force-exit goroutine does not call exitFunc when shutdown completes near the timeout boundary
- `TestSchedulerOnStopRespectsContext` (cron/scheduler_test.go): Verifies OnStop returns ctx.Err() when deadline expires with running jobs

## Decisions Made

1. **cron.Stop() under lock:** The internal `cron.Stop()` sends on a channel that the `run()` goroutine reads. Concurrent `Stop()` calls cause deadlock because the channel is unbuffered. Keeping `s.cron.Stop()` under the scheduler mutex prevents this, while the blocking wait on `cronCtx.Done()` happens outside the lock.

2. **EventBus backward compatibility:** `Close()` delegates to `CloseWithContext(context.Background())` so existing callers that call `Close()` directly (e.g., `defer bus.Close()` in tests) continue to work without code changes.

3. **Worker Manager API change:** `Stop(ctx context.Context)` is a breaking change to the public API. All internal callers and test callers were updated. External users will need to pass a context.
