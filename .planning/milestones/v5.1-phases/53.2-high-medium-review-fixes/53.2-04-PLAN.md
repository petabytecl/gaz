**B6 -- doStop cached services:**
In `app_run.go` `startServices()`, after computing the service set, cache it on the App struct. Add a field to the App struct in `app.go`:
```go
// cachedNonWorkerServices stores the service set computed during startServices,
// reused by doStop to avoid re-walking the container during shutdown.
cachedNonWorkerServices map[string]di.ServiceWrapper
```
In `startServices()`, after `services := a.collectNonWorkerServices()`, store: `a.cachedNonWorkerServices = services`.

In `app_shutdown.go` `doStop()`, instead of calling `collectNonWorkerServices()` again (line ~63), use the cached set:
```go
services := a.cachedNonWorkerServices
if services == nil {
    // Fallback if Stop called without Run/Start (e.g., during error cleanup)
    services = a.collectNonWorkerServices()
}
```
This eliminates the re-walk of the container during shutdown.

**B17 -- Critical-fail handler async-Stop logging:**
In `app_build.go` (lines ~65-69), the critical-fail handler calls `a.Stop(ctx)`. If `Stop` returns an error (including when stopOnce has already fired), log it:
```go
a.workerMgr.SetCriticalFailHandler(func() {
    log.Error("critical worker failed, initiating shutdown")
    go func() {
        ctx, cancel := context.WithTimeout(context.Background(), a.opts.ShutdownTimeout)
        defer cancel()
        if err := a.Stop(ctx); err != nil {
            log.Warn("critical-fail shutdown completed with errors", slog.Any("error", err))
        }
    }()
})
```
If the current handler does not log the Stop error, add the logging. If `Stop` returns nil when stopOnce has already fired, also add a check: verify whether `Stop` logs when called redundantly.
