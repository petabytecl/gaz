**A2 -- cron/scheduler.go OnStop (lines ~93-110):**
Remove `defer s.mu.Unlock()`. Instead: Lock, check `s.running`, if not running unlock+return nil. Set `s.running = false`, call `s.cron.Stop()` to get `cronCtx`, then `s.mu.Unlock()` (release before blocking). Then:
```go
select {
case <-cronCtx.Done():
    s.logger.InfoContext(ctx, "cron scheduler stopped")
    return nil
case <-ctx.Done():
    s.logger.WarnContext(ctx, "shutdown deadline exceeded")
    return ctx.Err()
}
```

**A3 -- eventbus/bus.go OnStop + Close (lines ~231-273):**
Add a new method `CloseWithContext(ctx context.Context) error`. Copy the existing Close() logic (snapshot subscriptions under lock, set closed=true, close tombstones, release lock) but change the per-subscription wait from unbounded `<-sub.done` to:
```go
select {
case <-sub.done:
    // drained
case <-ctx.Done():
    b.logger.Warn("shutdown deadline exceeded, some handlers not drained",
        slog.Int("remaining", remaining))
    return ctx.Err()
}
```
Change `OnStop` from `OnStop(_ context.Context)` to `OnStop(ctx context.Context)` and call `return b.CloseWithContext(ctx)`. Keep the existing `Close()` method for backward compat -- it calls `CloseWithContext(context.Background())`.

**A4 -- worker/manager.go Stop (lines ~143-164):**
Change signature from `Stop() error` to `Stop(ctx context.Context) error`. The method already has a `m.done` channel (or WaitGroup). Replace the unbounded `m.wg.Wait()` with:
```go
done := make(chan struct{})
go func() {
    m.wg.Wait()
    close(done)
}()
select {
case <-done:
    m.logger.Info("all workers stopped")
    return nil
case <-ctx.Done():
    m.logger.Warn("worker stop deadline exceeded")
    return ctx.Err()
}
```
If `m.done` channel already exists, use that instead of wrapping wg.Wait. Update the caller in `app_shutdown.go` line ~81 from `a.workerMgr.Stop()` to `a.workerMgr.Stop(ctx)`.

**A1 -- app_shutdown.go force-exit race (lines ~44-58):**
In the force-exit goroutine, after `<-timer.C` fires, add a non-blocking re-check of `done`:
```go
case <-timer.C:
    select {
    case <-done:
        return // shutdown finished between timer fire and this check
    default:
        msg := fmt.Sprintf("shutdown: global timeout %s exceeded, forcing exit",
            a.opts.ShutdownTimeout)
        a.getLogger().Error(msg)
        _, _ = fmt.Fprintln(os.Stderr, msg)
        callExitFunc(1)
    }
```

**A5 -- cron/internal/cron.go Stop waiter goroutine:**
The goroutine leak in `Stop()` (line ~302-315) is acceptable because the caller (cron/scheduler.go OnStop, now fixed with A2) has `select { case <-cronCtx.Done(): case <-ctx.Done() }`. The goroutine only survives until process exit. Add a doc comment to `Stop()`:
```go
// Stop signals the cron scheduler to stop and returns a context that is
// cancelled when all running jobs complete. The returned context should
// be used with a deadline: select { case <-ctx.Done(): case <-parentCtx.Done(): }.
// Note: if a job hangs indefinitely, the internal waiter goroutine will leak
// until process exit. Callers should use their shutdown context to bound the wait.
```

**A13 -- app_run.go handleSignalShutdown (lines ~140-180):**
The issue is that `defer signal.Stop(sigCh)` in `waitForShutdownSignal` (line ~128/143) runs when the function returns, but the watcher goroutine in `handleSignalShutdown` still reads from `sigCh`. Fix by synchronizing: the watcher goroutine should signal completion via a `watcherDone` channel, and `handleSignalShutdown` should wait on `watcherDone` before returning (so that `defer signal.Stop` in the caller runs AFTER the watcher exits). Pattern:
```go
watcherDone := make(chan struct{})
go func() {
    defer close(watcherDone)
    select {
    case <-sigCh:
        callExitFunc(1) // second signal = force exit
    case <-shutdownDone:
        return
    }
}()
err := <-shutdownDone
<-watcherDone // ensure watcher exits before signal.Stop runs
return err
```
If `handleSignalShutdown` does not currently have this goroutine pattern, add it. The key invariant: `signal.Stop(sigCh)` must not run while the watcher goroutine is still selecting on `sigCh`.
