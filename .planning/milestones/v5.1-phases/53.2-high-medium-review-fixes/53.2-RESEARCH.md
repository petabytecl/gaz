### Pattern 1: Shutdown Context Propagation (A1-A5, A13)
**What:** Every OnStop/Close must add `case <-ctx.Done()` alongside any blocking wait.
**When to use:** Any code that waits indefinitely in a shutdown path.
**Example:**
```go
// Source: CLAUDE.md Rule 3 + CONTEXT.md A2 fix sketch [VERIFIED: codebase]
func (s *Scheduler) OnStop(ctx context.Context) error {
    s.mu.Lock()
    if !s.running {
        s.mu.Unlock()
        return nil
    }
    s.running = false
    s.mu.Unlock() // Release lock before blocking

    cronCtx := s.cron.Stop()
    select {
    case <-cronCtx.Done():
        s.logger.InfoContext(ctx, "cron scheduler stopped")
        return nil
    case <-ctx.Done():
        s.logger.WarnContext(ctx, "shutdown deadline exceeded")
        return ctx.Err()
    }
}
```

### Anti-Patterns to Avoid
- **Lock-during-blocking-IO (Rule 1):** A2, B1 are new violations found. After fix, C1 linter prevents regression.

## Common Pitfalls

### Pitfall 1: ReplaceService Signature Change Ripple
**What goes wrong:** Changing `ReplaceService` from no-return to `error` breaks callers that don't handle the error.
**Why it happens:** 4 call sites (2 in registration.go, 1 in gaztest/builder.go, 1 in container_test.go) currently ignore the return.
**How to avoid:** The gaztest builder calls ReplaceService BEFORE Build() (it is called in Build()), so it should always succeed. The registration.go callers use `allowReplace` which also happens pre-Build. But the code must still check and return the error. Update all 4 sites to handle `error`.
**Warning signs:** Compile error at `gaztest/builder.go:179` and `di/registration.go:122,154`.

### Pitfall 2: Worker Manager Stop(ctx) Signature Change
**What goes wrong:** `manager.Stop()` currently returns `error` with no ctx parameter. Adding `ctx` changes the interface.
**Why it happens:** `app_shutdown.go:81` calls `a.workerMgr.Stop()` without ctx.
**How to avoid:** Change signature to `Stop(ctx context.Context) error`. Update caller in app_shutdown.go to pass shutdown ctx. Mock in gaztest may need updating.
**Warning signs:** Compile error at `app_shutdown.go:81`.

### Pitfall 3: AllowZeroWriteTimeout Default Flip (BREAKING)
**What goes wrong:** Any user relying on `DefaultConfig()` with streaming RPCs will hit validation failure because `AllowZeroWriteTimeout` flips from `true` to `false`.
**Why it happens:** Current default is `true`, meaning zero WriteTimeout is silently accepted. Fix changes default to `false` with `WriteTimeout: 30s`.
**How to avoid:** Document in CHANGELOG with migration path: set `allow_zero_write_timeout: true` or `write_timeout: 0` explicitly for streaming workloads. Tests that use DefaultConfig() must be updated.
**Warning signs:** Validation errors in server startup tests.

### Pitfall 4: Env-Var Convention Split (BREAKING)
**What goes wrong:** Users with env vars using double-underscore (e.g., `APP_DATABASE__HOST`) stop working after fix.
**Why it happens:** Line 132 in config/manager.go uses `"."` -> `"__"` for AutomaticEnv, line 374 uses `"."` -> `"_"` for RegisterProviderFlags. Fix adopts single underscore everywhere.
**How to avoid:** Document in CHANGELOG. The double-underscore convention was documented in options.go:25 and viper backend tests use it. Update tests at `config/viper/backend_test.go:237,264` and `config/options.go:25`.
**Warning signs:** Env var binding tests fail in config/ package.

### Pitfall 5: time.Sleep in Cron Internal Tests (Vendored)
**What goes wrong:** Blindly replacing all time.Sleep in cron/internal/ breaks timing-sensitive scheduler tests.
**Why it happens:** The cron internal package is vendored from robfig/cron. Some tests deliberately sleep to allow scheduled jobs to fire at specific cron ticks.
**How to avoid:** Categorize each sleep site. For job-wait sleeps, use channel signaling (the job can signal completion). For schedule-tick sleeps (waiting for cron to fire), these may need to remain as-is or use a mock clock.
**Warning signs:** Flaky cron tests after replacing sleeps.

### Pitfall 6: C1 Custom Linter False Positives
**What goes wrong:** The lockblockingio linter flags `defer mu.Unlock()` in functions that do NOT contain blocking operations.
**Why it happens:** Naive pattern matching of `defer mu.Unlock()` without checking whether the function body contains blocking calls.
**How to avoid:** The analyzer must walk the function body between the defer and the function exit to detect blocking operations (channel send/recv, wg.Wait, ctx.Done select, net.Dial, etc.). Provide `//nolint:lockblockingio` escape hatch.
**Warning signs:** Lint failures on safe lock usage patterns.

### A8: Eager Resolve Determinism
```go
// Source: CONTEXT.md A8 fix [VERIFIED: di/container.go:188-217]
func (c *Container) Build() error {
    c.buildOnce.Do(func() {
        var eagerServices []ServiceWrapper
        c.mu.RLock()
        for _, wrappers := range c.services {
            for _, wrapper := range wrappers {
                if wrapper.IsEager() {
                    eagerServices = append(eagerServices, wrapper)
                }
            }
        }
        c.mu.RUnlock()

        // Sort by name for deterministic resolution order
        sort.Slice(eagerServices, func(i, j int) bool {
            return eagerServices[i].Name() < eagerServices[j].Name()
        })

        for _, svc := range eagerServices {
            if err := c.resolveEager(svc); err != nil {
                c.buildErr = fmt.Errorf("di: building eager service %s: %w", svc.Name(), err)
                return
            }
        }

        c.mu.Lock()
        c.built = true
        c.mu.Unlock()
    })
    return c.buildErr
}
```
